# ניתוח וידאו סקוואט — כלי תרגול למאמן כושר

כלי מבוסס Computer Vision שמנתח תנועת סקוואט (מווידאו מוקלט מראש או ממצלמה חיה): מזהה שלד ונקודות גוף, מחשב את זווית הברך, סופר חזרות, ומודד את משכי הירידה והעלייה בכל חזרה. אפשר גם להגדיר יעד קצב אופציונלי (טווח שניות לירידה/עלייה) ולקבל עליו משוב.

**הכלי הזה לא נותן ציון טכניקה ולא קובע אם הביצוע "תקין"** — הוא מודד ומציג נתונים בלבד (זווית, קצב, השוואה ליעד קצב אם הוגדר), ומשאיר את השיפוט המקצועי למאמן.

## סטטוס נוכחי

פרויקט בתחילת דרכו, נבנה צעד-צעד:

- ✅ זיהוי תנוחה (pose estimation) על תמונה בודדת ועל GIF, כולל שרטוט שלד ונקודות גוף.
- ✅ חישוב זווית ברך דו-ממדית (אגן-ברך-קרסול) עם סף ביטחון וטיפול בנקודות חופפות.
- ✅ ספירת חזרות באמצעות מכונת מצבים (עמידה → ירידה → עומק → עלייה → עמידה), עם הגנה מפני ספירה כפולה ומפני אובדן זיהוי.
- ✅ מדידת משך ירידה/עלייה לכל חזרה, עם משוב קצב אופציונלי מול יעד שהמאמן מגדיר.
- ✅ בדיקות יחידה למנגנון הספירה והתזמון, עם רצפים מדומים (בלי צורך במודל).
- 🔲 סקריפט CLI לניתוח חי ממצלמה (`live_squat.py`) — כתוב, אך **טרם נבדק בפועל מול מצלמה אמיתית**.
- ✅ ממשק web מקומי בעברית ו-RTL ("מאמן התנועה שלי", `webapp/`), עם שרת שמזרים וידאו+נתונים מהמצלמה לדפדפן. ראו סעיף "ממשק web" בהמשך.
- ✅ מאמן חכם אופציונלי (LLM דרך Anthropic API, בצד השרת בלבד) שנותן דגש קצר בעברית אחרי כל חזרה ועונה על שאלות בצ'אט, מבוסס אך ורק על המדידות שכבר קיימות. כבוי כברירת מחדל (דורש `ANTHROPIC_API_KEY`) — האפליקציה עובדת באותה מידה בלעדיו, עם המשוב מבוסס-הכללים הקיים.
- ⚠️ **סטטוס בדיקה נוכחי (2026-09-18): הפעלת מצלמה + כפתור "התחל אימון" עדיין לא אומתו סוף-לסוף עם אדם אמיתי.** נמצא ותוקן באג אמיתי (WebSocket שלא התחדש אחרי ניתוק/הפעלה מחדש של השרת), אבל בבדיקה האחרונה המצלמה עצמה נתקעה (התברר שתהליך לא קשור תפס אותה) ולא הצלחנו עדיין לאשר זרימת וידאו תקינה מקצה לקצה. **יש לבדוק את זה בעצמכם לפני אימון אמיתי.**
- אין שמירת היסטוריית אימונים בין הפעלות, ואין ציון טכניקה (ולא מתוכנן להיות) — גם לא מה-LLM.

## דרישות

- Python 3.14 (נבדק עם 3.14.7; ראו הערה על גרסאות אחרות בהמשך).
- [ultralytics](https://github.com/ultralytics/ultralytics) 8.4.x (מודל YOLO11-Pose)
- [opencv-python](https://github.com/opencv/opencv-python) 5.x
- [fastapi](https://fastapi.tiangolo.com/) + [uvicorn](https://www.uvicorn.org/) (רק לממשק ה-web, `webapp/`)
- [anthropic](https://github.com/anthropics/anthropic-sdk-python) (רק אם רוצים להפעיל את המאמן החכם - אופציונלי לגמרי)
- מצלמת מחשב (לסקריפט הניתוח החי ולממשק ה-web)

## שימוש

### בדיקת זיהוי תנוחה על תמונה
```bash
python scripts/test_pose.py <נתיב לתמונה>
```
שומר עותק עם השלד ל-`<שם>_pose.<סיומת>`. התמונה צריכה להכיל אדם עם כל הגוף (כולל כפות רגליים) בפריים.

### זיהוי תנוחה על GIF
```bash
python scripts/test_pose_gif.py <נתיב ל-GIF>
```

### חישוב זווית ברך + גרף
```bash
python scripts/knee_angle_gif.py <נתיב ל-GIF>
```

### ספירת חזרות + תזמון + משוב קצב, על GIF
```bash
python scripts/rep_counter_gif.py <נתיב ל-GIF>
```
שומר אנימציה (`_reps.gif`) וגרף (`_reps_timing.png`), ומדפיס לקונסול סיכום לכל חזרה (משך ירידה/עלייה, ומשוב קצב אם הוגדר יעד ב-`PACE_TARGET` בראש הקובץ).

### ניתוח חי ממצלמה
```bash
python scripts/live_squat.py
python scripts/live_squat.py --side L                                  # לדלג על בחירה אינטראקטיבית
python scripts/live_squat.py --pace-descent 2.0 3.0 --pace-ascent 1.0 2.0  # להפעיל יעד קצב (כבוי כברירת מחדל)
```
בהפעלה: עומדים בצד למצלמה (כל הגוף וכפות הרגליים בפריים), בוחרים צד מדידה (L/R — נשאר קבוע לכל הסט), ועומדים ישר עד שהמערכת מזהה עמידה יציבה ומתחילה לספור. יציאה עם `Q`. **לא נשמר וידאו לדיסק.**

### בדיקות יחידה
```bash
python scripts/test_rep_counter.py
```
בודק את מנגנון הספירה, ההגנה מפני ספירה כפולה, הטיפול במדידות חסרות/אובדן זיהוי, מדידת התזמון, ומשוב הקצב — הכול עם רצפים מדומים, בלי להריץ מודל.

## ממשק web — "מאמן התנועה שלי"

ממשק מקומי בעברית ו-RTL, עם עיצוב מותאם (רקע כחול כהה, כרטיסים, ירוק מנטה לפעולות/הצלחות, כתום להנחיות צילום). מריץ את אותה לוגיקה בדיוק (`scripts/rep_logic.py`, ללא שינוי) על שידור חי מהמצלמה.

**ארכיטקטורה:** שרת Python (FastAPI) פותח את המצלמה ישירות עם OpenCV (בדיוק כמו `live_squat.py`, לא דרך מצלמת הדפדפן), מריץ עליה YOLO+`rep_logic.py`, ומזרים כל פריים מעובד (עם שלד) + נתוני מצב (זווית/מצב/מונה חזרות) לדפדפן דרך WebSocket. הדפדפן הוא תצוגה בלבד — כל העיבוד מקומי, בלי שמירת וידאו לדיסק.

**הפעלה:**
```bash
python webapp/server.py
```
ואז פותחים **http://localhost:8000** בדפדפן.

**שימוש:**
1. לפני האימון: בוחרים צד צילום (נשאר קבוע לסט), אפשר להגדיר יעד חזרות ויעד קצב (אופציונלי, כבוי כברירת מחדל), ולוחצים "הפעל מצלמה".
2. בתצוגה המקדימה עומדים מהצד למצלמה עם כל הגוף וכפות הרגליים בפריים — עד שמופיע "מוכן! אפשר להתחיל אימון" (מבוסס על הנקודות שהמערכת באמת מזהה, לא הדמיה).
3. "התחל אימון" — וידאו חי עם שלד, מונה חזרות, מצב תנועה בעברית, ופאנל "המאמן" (צ'אט) עם הודעת פתיחה, סיכום קצר אחרי כל חזרה, ומשוב קצב אם הוגדר יעד. אפשר לשאול את המאמן שאלות (למשל "כמה חזרות עשיתי?") — התשובות מבוססות על הנתונים שנמדדו בפועל בלבד. אם המאמן החכם (LLM, ראו הסעיף הבא) מוגדר ופעיל, מוצגת תגית "🧠 מאמן חכם פעיל" בראש פאנל הצ'אט.
4. "השהה"/"המשך" עוצר/ממשיך את הניתוח (המצלמה נשארת דלוקה, אבל בלי YOLO/ספירה בזמן השהיה). "סיים אימון" משחרר את המצלמה ומציג סיכום: מספר חזרות, משכי ירידה/עלייה לכל חזרה, סוג מדידה (תקפה/משוערת), והדגשים שניתנו.

**סטטוס בדיקה (עודכן 2026-09-18):** נמצא ותוקן באג אמיתי בכפתור "התחל אימון" (חיבור WebSocket שלא התחדש אחרי ניתוק/הפעלה מחדש של השרת — תוקן, ואומת שהחיבור-מחדש עובד). **עם זאת, בבדיקה האחרונה המצלמה עצמה לא הגיבה** (ככל הנראה תהליך אחר תפס אותה) **ועדיין לא אומתה זרימת וידאו תקינה ו"מוכנות" אמיתית מקצה לקצה עם אדם מול המצלמה.** לפני אימון אמיתי, ודאו בעצמכם שהתצוגה המקדימה מציגה וידאו חי (לא תמונה שחורה/קפואה) ושמוכנות אכן מתקבלת כשעומדים בפריים.

## מאמן חכם (LLM, אופציונלי) — Anthropic API

מעל המשוב הקבוע מבוסס-הכללים (שנשאר פעיל תמיד, ללא תלות בזה), אפשר להפעיל "מאמן חכם" שנותן דגש קצר נוסף בעברית אחרי כל חזרה ועונה על שאלות חופשיות בצ'אט - **דרך Anthropic API, בצד השרת בלבד**.

**ספק ומודל:** Anthropic, מודל `claude-haiku-4-5` - נבחר במכוון (לא ברירת המחדל של הפרויקטים החדשים) כי זו קריאה קצרה וזולה ברקע (משפט אחד בעברית) שרצה אחרי כל חזרה בלי לעצור את זרם המצלמה, וחשוב שתהיה מהירה וזולה. אפשר להחליף בקלות ל-`claude-opus-5` ב-`webapp/coach_llm.py` אם רוצים תשובות עשירות יותר, במחיר זמן/עלות גבוהים יותר.

**איך מגדירים מפתח API:**
```bash
export ANTHROPIC_API_KEY="sk-ant-..."   # בטרמינל שממנו מריצים את webapp/server.py, לפני ההרצה
python webapp/server.py
```
בלי המשתנה הזה, המאמן החכם כבוי אוטומטית והאפליקציה ממשיכה לעבוד רגיל עם המשוב מבוסס-הכללים בלבד (אין צורך בשום שינוי קוד). **המפתח לעולם לא נשלח לדפדפן, לא מקודד בקוד, ולא נכתב ליומן** - הוא נקרא רק על ידי `webapp/coach_llm.py` בצד השרת, דרך משתנה הסביבה.

**מה נשלח למודל:** רק טקסט/מספרים - מספר החזרה, משכי ירידה/עלייה, האם המדידה משוערת, יעד הקצב (אם הוגדר) והמשוב הקיים המחושב לפי הכללים; לשאלות צ'אט - גם צד המדידה, יעד החזרות, ופירוט כל החזרות שהושלמו בסט. **לא נשלחות תמונות או וידאו בשלב הזה.**

**הגבלות שהוטמעו ב-system prompt:** להתבסס אך ורק על הנתונים שסופקו, לא להמציא נתונים/תצפיות, לא לקבוע אם הטכניקה תקינה/לא תקינה, לא לאבחן פציעה, לא לטעון שראה תמונה/וידאו, ולהגיד בפירוש כשהמידע לא מספיק.

**התנהגות בכשל/איטיות:** המשוב מבוסס-הכללים נשלח תמיד מיד, בלי לחכות ל-LLM בכלל. קריאת ה-LLM (לדגש נוסף אחרי חזרה, או לתשובת צ'אט) רצה ברקע (fire-and-forget) עם פסק-זמן של 8 שניות; אם היא נכשלת, לוקחת יותר מדי זמן, או שאין מפתח מוגדר - האימון ממשיך כרגיל, וללא הודעה מ-LLM (לדגש אחרי חזרה) או עם התשובה מבוססת-הכללים הקיימת (לשאלת צ'אט).

**נבדק בפועל** (`webapp/coach_llm.py`, בלי מצלמה): (1) בלי מפתח מוגדר - המאמן החכם כבוי, אין קריאת רשת בכלל. (2) עם מפתח לא תקין - נשלחת קריאה אמיתית ל-Anthropic שנכשלת (401), והקוד נופל בחזרה ל-None בלי לקרוס ובלי לחשוף פרטים. (3) עם קריאת המודל מדומה (mock) - שרשרת השילוב המלאה בקוד השרת (הודעת חזרה עם קידומת 🧠 ותגית `source:"llm"`, נפילה לתשובה מבוססת-כללים כשה-LLM מחזיר כישלון) נבדקה ועובדת. **קריאה מוצלחת אמיתית מול Anthropic לא נבדקה בסביבה הזו** (אין כאן מפתח API אמיתי) - יש לבדוק עם מפתח אמיתי משלכם.

## הגדרות ניתנות לשינוי (`scripts/rep_logic.py`)

| קבוע | ברירת מחדל | משמעות |
|---|---|---|
| `STAND_ANGLE` | 160° | מעל זה נחשב "עמידה" |
| `DEPTH_ANGLE` | 100° | מתחת לזה נחשב "הגיע לעומק" |
| `CONFIRM_SEC` | 0.12s | זמן רציף נדרש לפני שמצב נחשב "מאושר" (מונע ספירה כפולה מרעידות) |
| `MAX_MISSING_SEC` | 0.5s | אובדן זיהוי רציף מעבר לזה מאפס התקדמות חלקית של חזרה |
| `PACE_TARGET_EXAMPLE` | ירידה 2–3s, עלייה 1–2s | **ערכי דוגמה לבדיקת התוכנה בלבד — לא המלצת אימון** |

כל הספים האלה ניתנים לשינוי בקוד לפי הצורך.

## הערות חשובות

- הזווית מחושבת רק כשלושת נקודות הגוף הרלוונטיות (אגן/ברך/קרסול, בצד אחד קבוע) מזוהות בביטחון ≥0.7; אחרת המדידה מסומנת כחסרה.
